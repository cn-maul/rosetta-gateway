## 1. 全量审计执行结论（2026-10-20）

11 个子域合计给出 **200 条分级问题**（含测试透镜中的重复项）。按统一的生产影响口径去重后，
确认 **12 个生产 P0、50 个生产 P1**；另有 **6 个测试/CI P1 缺口**和若干关键 P2 边界问题。
问题集中在资金事务原子性、协议状态机、路由并发、前端/后端契约、部署安全和测试门禁。

当时最重要的五条判断：

1. **资金正确性已经失去一致性边界。** `balance_pending` 的结算不是单事务，存在重复结转、
   重复扣款、漏收和把「无限额」改成「有限额」的路径。
2. **「上游已计费、用户应收」之间没有可靠闭环。** 重算不补扣余额、累计表不更新、
   归档销毁待重算标记、charge 吞错，且没有对账任务。
3. **配额预占没有崩溃恢复契约。** `reserved_tokens` 是终身预占；一次崩溃或强杀可永久
   冻结 key/user 的终身额度。TPM 还有一条早退路径漏退预占。
4. **协议层和路由层仍有静默语义漂移。** `reasoning_effort=max` 被静默降成「不思考」；
   健康上游目标被 half-open 全局互斥位串行化；跨协议编号空间和流式状态机存在串味。
5. **「测试全绿」不能证明系统正确。** 多条测试把错误行为固化成期望，或复制生产分支、
   正则提取路由、只测单 Store。CI 当时没有真实 mux、前端契约、崩溃恢复和跨 Store 资金并发门禁。

### 9.2 已验证无问题或基础较好的区域（2026-10-20 结论）

- SQL 注入面：store 内 SQL 拼接仅限包内白名单常量、占位符和字面量排序方向。
- `balance_charges` 复合主键迁移：单事务重建、失败回滚、迁移幂等。
- usage 剪枝的聚合与删除：同一事务、同一 rowid 临时表谓词，剪枝前后总量守恒。
- `usage_daily_rollups` 主键重建：非空表拒绝启动而非静默丢历史。
- 管理面 81 条路由的匿名/普通用户/管理员矩阵：未发现匿名可达受保护 handler 或直接跨用户 key 越权。
- 密码重置、改密与 bootstrap 设密通过 `auth_version + 1` 原子失效旧会话。
- 出站 `ResponseController.SetWriteDeadline` 的用法未复发历史「包装 writer 丢帧」；SSE writer 有并发锁。
- Anthropic 块状态机、缓存 token 三桶拆分的主要路径。
- 入站协议解码的重复顶层键拒绝、非对象顶层处理、结构化解码基础检查。
- 安全基础面：SQL 参数化、静态文件服务、上游重定向控制、密码哈希与 JWT 算法固定。
