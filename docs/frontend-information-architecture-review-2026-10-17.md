# Rosetta Gateway 前端信息组织评审与改版方案

评审日期：2026-10-17。基于当前工作区源码（包含未提交的前端调整），以及本地 `heroui-3.2.6` 的实际组件与样式源码。

预览方式：当前源码构建到聊天独立目录，在只接受 GET 的本地示例 API 上预览总览、可用模型、上游、路由和请求明细。预览数据全部为构造数据，只用于验证排版与操作路径，不能据此评价真实网关的运行质量。未连接生产数据库、未修改现有业务代码或部署产物。

## 1. 结论与产品定位

当前问题主要来自信息结构：把“有关联的数据”合并进页签，却没有围绕“用户要完成的任务”组织页面。视觉上又大量使用同权重卡片，让普通字段、关键状态和操作争夺注意力。

建议将管理员界面定位为 **AI 流量控制台**，围绕五件事组织：

1. 运行：最近流量、错误、延迟和需要处理的异常。
2. 转发：客户端使用哪个公开模型名，它按什么顺序请求哪些上游模型。
3. 接入：上游是否配置就绪，凭据与模型能否工作。
4. 访问：谁能使用哪些公开模型，受哪些余额、配额和限速约束。
5. 排障与费用：某次请求去了哪里、为什么失败、记录了多少用量和费用。

普通用户界面围绕“接入和使用”：复制接入地址 → 选择可用模型 → 创建 API 密钥 → 查看自己的调用与余额。

保留现有 Vue 3 架构，继续借鉴 HeroUI 的组件视觉和交互。优先重排信息，再统一组件；当前阶段没有必要为了换组件库迁移整站到 React。

## 3. 推荐导航与对象关系

管理员侧栏建议 8 个入口，分组帮助定位，但不再混放个人工作台：

```text
运行
  网关总览
  请求日志
  用量与费用
网关配置
  模型与路由
  上游服务
  用户与权限
管理
  账户与充值
  系统设置
底部头像菜单：账号设置、退出
```

普通用户侧栏：我的总览、可用模型、API 密钥、我的调用、余额与账单。接入说明放在我的总览和 API 密钥页，账号设置位于头像菜单。

管理员与普通用户可以共用布局组件与数据表组件，但应拥有各自的导航配置、标题和总览内容。权限继续由后端控制，不靠切换菜单实现。

必须区分三种“模型”：

| 对象 | 产品名称 | 页面归属 | 作用 |
|---|---|---|---|
| public_name + route/targets | 公开模型 / 模型与路由 | 网关配置主入口 | 客户端传入的 model，指向有序上游链 |
| upstream_models | 上游模型 | 上游详情的模型页签 | 某个供应商实际提供的模型与价格、能力 |
| model_groups | 统计归并 | 用量与费用 → 模型分析中的辅助配置 | 合并统计身份，不参与路由或授权 |

“用户分组”统一称“权限分组”，避免与统计归并混淆。`provider/model` 直连方式继续明确展示在接入说明中，不让它被误认为普通公开路由的同义词。

关联信息通过对象链接贯通：模型与路由 → 上游详情 → 该上游模型 → 相关请求；用户 → 此人的密钥、权限与余额。放进同一个父页面的不同页签，并不能替代这种带对象上下文的连接。

## 4. 逐页布局方案

### 网关总览

从上到下：

1. 页标题与“全站”作用域、统计时间范围、最后更新时间、刷新。
2. 需要处理的事项：上游未就绪、首选探测异常等。每项有对象名、原因和处理入口；无异常时压缩为一行。缺少健康数据时写“未知”，不宣称全站正常。
3. 四个摘要：请求数、错误率（错误数 / 请求数）、平均首字时间、记录费用。卡片附样本/口径；零请求显示“暂无请求”，不能显示 0% 错误后宣称稳定。
4. 主区域为请求量或 Token 的时间趋势；旁边或下方是异常对象清单。窄屏垂直排列。
5. 最近失败请求（少量行），可进入带相同时间范围和错误筛选的请求日志。

实时/最新就绪状态与所选区间统计分区标注。“最近 7 天错误率”不能被命名为“当前健康”。输入/输出 Token、缓存、速度和排行榜放到用量与费用页。

个人总览调整为：接入地址和快速开始 → 余额/配额提醒 → 我的请求与费用 → 最近失败调用。管理员首次引导为“添加上游 → 导入模型 → 配置公开模型路由 → 给使用者分配权限/密钥”；普通用户引导为“选模型 → 创建密钥 → 复制接入配置”。

### 模型与路由（管理员主入口）

一级对象是公开模型，不是供应商。默认表格列：

```text
公开模型名 | 配置/目标提示 | 首选目标 | 后备数量 | 故障转移 | 更多
```

名称链接进入稳定详情 URL。详情上方摘要显示公开名、启停、故障转移开关；主体为完整有序上游链：

```text
首选    上游 A / 模型 X    [配置就绪] [首选探测异常]
后备 1  上游 B / 模型 Y    [配置就绪]
后备 2  上游 C / 模型 Z    [未启用]
```

顺序必须显式编号；支持上移、下移、设为首选，不只支持拖拽。禁用目标仍留在链中可见。编辑前后可检查链的变化，保存区固定在编辑页底部。路由链编辑采用完整页面；请求或模型的补充详情才使用 Drawer。

路由详情中的“首选探测异常”并不等于整条路由不可用。当前接口缺少完整运行时目标资格与熔断快照时，只展示已知事实和全链配置。

### 上游服务

默认按表格比较。列：名称、协议、配置状态、就绪状态、模型/凭据摘要、更多。Endpoint 放名称次行或详情中，代理、超时、余额脚本放详情。

状态须分开：

- 已停用：配置不参与转发。
- 已启用 / 未就绪：显示 ready_reason，例如无可用凭据。
- 已启用 / 已就绪：仅表示运行时具备基本接入条件，不保证每个模型推理成功。
- 模型探测失败：属于具体模型的探测结果，不能覆盖成供应商整体结论。

详情保留现有独立页面，顶部面包屑“上游服务 / 名称”，摘要与操作一行；主体 Tabs：模型、凭据、连接设置。模型表占满宽度。模型详情内集中维护能力、三档价格、最近真实调用质量、探测结果，并分别标明口径。

凭据若采用当前的“切换一把会停用原凭据”语义，应使用“设为当前凭据”等明确操作；不要把互斥选择呈现成相互独立的多个开关。余额按凭据展示查询时间与原币种，查不到说明原因。

### 可用模型（普通用户）

默认按表格横向比较：公开模型名、首选参考价格（输入/输出）、首选目标探测、详情。可保留可选卡片视图，但只留名称、参考价格和一项状态。

顶部优先搜索模型与复制接入信息；完整探测曲线、三档价格和规则说明在详情中。时间范围控件属于探测历史区域，不占据模型清单的主操作位置。

多目标路由明确提示“按实际命中目标计费；这里显示首选参考价”。无数据显示“未探测”；未配置价格显示“未配置”，不能写“免费”。本页清单只代表用户层可见范围，选择具体 API 密钥后还可能因 key 级白名单进一步收窄。

### 请求日志

独立入口，默认列约 7 项：状态、时间、公开模型、实际去向、调用密钥、首字/总耗时、费用。Token 和速度可在列设置中启用或在详情查看。模型名与目标可换行但不挤成单字列。

一条工具栏统一时间、状态、模型、密钥筛选；已启用条件显示为可移除 Tag，重置入口固定。分页与页数位于表尾。CSV 导出继承当前筛选，保留现有截断提示。

行内显示简短失败原因；点击打开 Drawer：公开模型 → 实际模型、流式标记、错误原文、用量、延迟和费用。已有 `route_trace` 时，按记录顺序展示目标与 `fail_switch` 等决策及原因，并保留原文；这能直接回答“为什么走备用”与“为什么失败却没切换”。轨迹缺失不等于“没有发生转移”，不能补造步骤。

列表与详情保持同一筛选和滚动位置。当前 history 响应没有独立的 provider_id/provider_name，也没有 ingress_protocol；供应商、入口协议若要成为稳定列，需由后端补充。不能用当前路由配置反推过去的实际供应商。更完整的每次尝试耗时、重试 span 和请求正文属于后续采集能力。

### 用量与费用、账户与充值

用量与费用负责区间分析：请求、Token、费用及质量，按上游/模型/用户等已有维度汇总，使用统一时间范围。每个指标有清楚单位与分母。统计归并放在模型分析附近。首阶段沿用现有统计窗口；小时级流量需后端提供分桶后再上。

账户与充值负责账户余额、充值/调整流水、操作者和备注。管理员看到全站账务管理，普通用户看到个人余额和账单。历史记录费用、上游实际账单与用户余额分开命名；当前固化费用不能直接命名为采购成本或利润。

人民币余额、用户 Token 配额、API Key 配额和 RPM/TPM 是不同约束。任一层不足都要指出具体原因，不能泛称“额度不足”，不能提示用户级配额耗尽后仅更换密钥就能解决。

### 用户与权限、系统设置

用户与权限内使用用户、权限分组、API 密钥三个同级子页；用户详情可直接看到其组、密钥和当前有效限制。新增用户、密钥使用短表单；模型/IP/限额等高级限制用 Disclosure 渐进展开，同时保留有效规则摘要。

系统设置保留全局模型默认、超时/流式保护、全局故障转移参数、用量归档、配置导入导出。对象价格回到上游模型；个人密码回到账号设置。UI 不再暴露 position、数据库 id 等内部术语，必要标识保留在详情中用于排障。

## 5. 从本地 HeroUI 3.2.6 选择的组件

以下均核对过本地 `packages/react/src/components` 与对应 MDX/CSS，未按其他版本的组件名称猜测。

| 信息任务 | 首选组件 | 具体使用方式 | 本地参考文件（相对 HeroUI 根目录） |

| 配额占用 | Meter | 用于已用/总配额；不限额用文字，不能伪造进度比例 | `packages/styles/components/meter.css` |
| 短表单/确认 | Modal / AlertDialog | 新建上游、API Key 一次性明文、删除确认 | `packages/styles/components/modal.css`、`alert-dialog.css` |
| 少数摘要 | Card / Surface | 只承载关键指标或明确对象摘要，避免 Card 内再套 Card | `packages/styles/components/card.css`、`surface.css` |
| 数据反馈 | Skeleton、EmptyState、FieldError、Toast、Pagination | 加载、无数据、无权限、失败、过期分开处理；提交结果短反馈 | 对应同名组件目录与 CSS |

本地库没有可直接承担网关路由拓扑的专用组件。首阶段以有序列表配合 Surface、Chip 和按钮表达路由链。侧栏用 Vue RouterLink 与分组布局实现。趋势图、探测时间条属于业务可视化，不能说成“HeroUI 自带图表”。

## 6. Vue 与 HeroUI 的实际落地方式

项目 `web/package.json` 使用 Vue 3；本地 `@heroui/react@3.2.6` 要求 React 19 等 peer dependencies，不能直接把 TSX 组件导入 Vue 页面。

推荐路线：

1. 保留 Vue 3 + Vue Router + 当前 API 契约，先改导航、数据分区和布局。
2. 从本地 HeroUI 抽取状态、色彩、密度、布局与组件结构，封装成项目内 Vue 组件：PageHeader、DataToolbar、DataTable、StatusChip、DetailDrawer、EmptyState。
3. 已有 Tabs、AppModal 和主题变量继续使用并补齐行为，不重复造轮子。
4. Table 的排序、选择、列显隐，Drawer 的焦点管理/关闭后焦点返回，Tabs 的键盘导航，都必须实现与验证；复制 CSS 不会获得 React Aria 的行为。
5. `@heroui/styles` 有 CSS 导出，但本地入口及组件源码包含 Tailwind v4 的 `@apply` 等处理要求；项目目前未接入该构建链。先统一现有移植样式，若要整包接入，再单独评估构建与重置样式冲突。不要把样式文件当成无需处理的浏览器即插即用文件。

React 迁移只在团队决定以后完整采用其 React Aria 体系时单独立项；不是本轮信息组织改版的前置条件。

## 8. 视觉与交互规则

- 清单优先“横向字段可比较、纵向对象可扫描”。摘要只保留少数重要指标；详情承载完整信息。
- 页面标题只出现一次。顶栏用于位置/作用域，页面标题用于任务与主动作，不再重复同一句标题占两行空间。
- 标题建议统一 22–24px，正文 14px，辅助文字 12px，指标 26–30px；当前不同页面的 17px/26px 标题应统一。
- 主内容间距以 8/16/24px 为基准；列表行建议 48–56px，表单字段约 36–40px。触屏按钮有效触达面积增大，避免靠缩字适配。
- 主体区域按对象分区，不按“凡是内容都套大卡片”分区；表格和工具栏共享一个视觉区域。圆角建议容器 12–16px、输入与按钮 8–12px、状态小圆角；通过主题 token 实现。
- 中性灰承载常规信息；品牌色用于主操作/当前导航；红色表示明确失败，橙色表示风险或降级，未知/未测用灰色。颜色与文字同时使用。
- 名称列保留足够宽度，必要时两行显示；数值右对齐并使用等宽数字。不要为塞更多列把名称挤到只剩首字符。
- 桌面优先保证主要列可读；中等宽度自动隐藏次要默认列、详情下钻；手机用摘要行+详情。实在必要时只让数据表横向滚动，不能让整页溢出。
- 下钻、返回、刷新保留 URL 内的页签/筛选/页码。URL 作为单一状态源，从查询参数派生页面状态。
- 错误原因、当前生效限制、价格口径必须可点击查看或直接可读，不能只依赖原生 title 悬停。
- 空数据、未配置、未探测、无权限、加载失败、数据过期分别展示；保留当前已实现的旧数据提示与权限隔离。

## 9. 实施顺序与验收

| 阶段 | 修改范围 | 直接收益 | 验收重点 |
|---|---|---|---|
| P0：先让信息能找到、状态可信 | 角色导航与标题；个人余额退出管理员总览；ready 原因、首选参考价与探测口径；普通用户 API 密钥/账号设置入口；旧路由精准映射 | 消除错误心智模型和误读 | 两个角色入口准确；未就绪不会显示成已可用；旧 keys/routes 链接到达正确子页 |
| P1：改主路径和密度 | 模型与路由主入口；上游默认表格；日志独立入口与详情；总览四指标+异常清单；价格靠近模型对象 | 减少找页面、记名字和横向扫视 | 能从公开名找到完整目标链；从错误直接定位对象；长名称可辨认 |
| P2：统一组件与补数据 | DataToolbar/DataTable/Drawer；分析页与统计归并；需要时补链摘要、首字样本数等后端聚合 | 页面行为一致，减少重复实现 | URL 状态可复现；无数据/失败/过期独立；响应式与键盘流程可用 |

首轮建议先完成“管理员导航 + 总览 + 模型与路由 + 上游列表”四块，再复用相同规则到日志、账务与个人工作台。无需一次推倒所有页面。

采用实际任务验收：

1. 新管理员能从空状态完成上游接入与公开模型配置，每步都有明确下一步。
2. 找到某公开模型的首选、后备顺序和故障转移开关，不需要先猜“上游与模型”的子页签。
3. 上游启用但无凭据时，列表直接给出未就绪原因。
4. 看到失败请求后能在当前上下文查看原因、实际目标和费用，返回仍保留筛选与页码。
5. 普通用户能直接找到 API 密钥、接入地址与个人改密，不进入管理员术语页面。
6. 在 1440、1280、1024、768、390px 宽度检查长模型名、无数据、部分失败与多路由场景；表格必要的局部横滚与整页溢出分开判断。
7. 数据缺失不会被呈现为 100% 可用、0 秒延迟或免费；所有模拟页面均显式标注示例数据。
