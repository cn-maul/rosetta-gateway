## 二、P1 问题（建议本轮修复）

### P1-1 · 批量落库整批失败 → 最多 50 条用量与扣费静默丢失，导致用户免单

**位置**：`cmd/gateway/main.go:2728-2748`（`usageRecorder.flush`）+ `internal/store/usage_dao.go:209-212`

`CreateUsageRecordsBatched` 是「全有或全无」的单事务多值 INSERT，失败即整批回滚。`flush` 遇错只打一条 ERROR 就 `return`——**记录已从队列出队，不重试、不落补偿队列**。

```go
costs, err := u.db.CreateUsageRecordsBatched(ctx, batch)
if err != nil {
    u.logger.Error("failed to record usage (batched)", ...)
    return   // ← 整批丢失，无重试
}
```

**影响**：一次瞬时写失败（SQLITE_BUSY / 磁盘错误 / 主键冲突）连带丢掉整批最多 **50 条**（`usageBatchSize = 50`）usage 记录。这些请求**既不入报表、不计配额、也不扣余额**——用户实际消耗了上游 token 却完全免单，且配额被永久放宽。**只需一次写池故障即可触发，不需要攻击者。**

**修复建议**：失败时将整批回灌队列头部并加入退避重试；或降级为逐条落库以缩小爆炸半径。至少加失败计数指标以便告警。

### P1-2 · 查价失败即永久记 0，该条请求完全免单且无自动修复

**位置**：`internal/store/usage_dao.go:327-348`（`freezeUsageCost`）

读池抖动时 `cost_total` 固化为 0，**并同时导致余额扣费为 0**（`main.go:2817` 把同一个 cost 传给 `charge`）。只记 WARN，无落盘线索。

经全仓 grep 确认：`RecomputeCost` 在生产代码中**没有任何调用点**（仅 `main.go:2737` 注释提及与 `usage_dao.go` 自身定义），即补救完全依赖人工调用。

**修复建议**：落 `usage_state='cost_pending'` 标记，由后台任务批量 `RecomputeCost`；至少让 WARN 可被日志告警捕获。

### P1-3 · 欠费用户的费用零头永久漏收（代码注释已自认）

**位置**：`internal/store/balance_dao.go:465-496`

`ErrInsufficientBalance` 分支直接 `return`，`defer tx.Rollback()` 把同事务内刚累加的 `balance_remainder` 一并撤销；调用方 `main.go:2820-2826` 只记 ERROR，**确实没有重试**。占位行回滚后，若调用方不重试，该笔费用永久消失且无流水，对账查不出。

**修复建议**：按注释建议记入独立待结算流水，或在欠费分支单独提交余数累加（需配套去重键）。

### P1-4 · `requireAdmin` 把「ID 为空的用户」当作管理员放行（fail-open）

**位置**：`internal/admin/user_admin_handler.go:138-154` — 已复核代码确认

```go
if u.ID == "" {
```

这是**全仓唯一的「空 ID = admin」判定**，与全仓 fail-closed 口径相反。对照：`key_handler.go:525-528`、`usage_handler.go:178-180`、`group_handler.go:311-314` 均显式拒绝空 ID，`ChangePassword`（`user_admin_handler.go`）也显式拒绝。

### P1-5 · 登录限速只有 IP 维度，无账号维度

**位置**：`internal/admin/user_handler.go:155-164,260-267`（限速器键为 `ClientIPOf(r)`）+ `internal/server/server.go:283-301`

阈值 10 次/分钟/IP、冷却 1 分钟。多出口 IP（NAT 池、云主机、代理池）针对同一 admin 账号可**并行爆破**，实际强度远低于 PBKDF2 成本所能支撑的水平。（改密路径已有按用户归键，`user_admin_handler.go:862`。）

**已核查不构成绕过**：大小写/Unicode 不构成绕过（`COLLATE NOCASE` + `validUsername` 仅允许 ASCII）；`X-Forwarded-For` 不被采信（`server.go:198-204`）。

**修复建议**：叠加第二个按 `user_id` 归键的计数，阈值可低于 IP 维度，成功登录才清零。

### P1-6 Anthropic 入口的 effort 夹取被 `budget_tokens` 静默旁路 —— ✅ 已修复（2026-10-11）

**位置**：`internal/inwire/anthropic.go:229-231` + `cmd/gateway/main.go`
（`applyThinkingCapability` 的 anthropic 分支）

**原问题**：`ToRosetta()` 同时保留了客户端原始 `Thinking.BudgetTokens`；
`applyThinkingCapability` 在 anthropic 分支只改 `Effort`、**不碰 `BudgetTokens`**。
而 rosetta 的 `plan()` 判据是 `if b := BudgetTokens; b <= 0 { ... }`
——**只要 BudgetTokens 非零就原样透传，Effort 完全不参与**。

**可复现推理链**：客户端发 `budget_tokens=5000` → 映射 `RawEffort="medium"`
→ 模型配 `effort_levels=[high]` → `Clamp` 得 `Effort="high"`，日志显示「已夹取到 high」
→ **但上游实收 `budget_tokens=5000`（medium 档）**。

**修复**（采纳方案 A：`effort_levels` 为硬约束）：anthropic 分支夹取后显式
`req.Thinking.BudgetTokens = 0`，交回 SDK 的 `anthropicBudget()` 三档表折算
（low=2048 / medium=8192 / high=32768）。置 0 而非网关侧自行计算
——折算表在 SDK 那边，网关再维护一份必然随 SDK 漂移。

**回归守卫**：`cmd/gateway/effort_levels_test.go` 新增

| 测试 | 钉住什么 |
|---|---|
| `TestApplyThinkingCapability_Anthropic预算与夹取一致` | 三格：变强 / 不变 / 变弱三个方向都不得漏用客户端原值 |
| `TestApplyThinkingCapability_OpenAI系不动预算` | 改动边界：OpenAI 两条路径不碰 `BudgetTokens` |

> **旧测试为什么漏掉它**：`TestApplyThinkingCapability_档位处理` 只断言
> `EffortRaw` 与 `Effort` 两个字段，而这两个在 bug 存在时**都是写对的**
> —— 错的是第三个字段 `BudgetTokens`，恰恰是 rosetta `plan()` 唯一认的那个。
> 新测试改为断言**最终发往上游的 budget_tokens**，即整条链路的真正落点。
>
> **已验证该测试确实能抓住这个 bug**：临时回退修复后三格全红
> （`BudgetTokens = 5000，仍是客户端原值`），恢复后全绿。

**影响**：修复前思考强度与计费档位不匹配且无任何报错；修复后 Anthropic 路径的
`effort_levels` 真正生效。OpenAI 两条路径不受影响（`effortWire()` 里 `EffortRaw`
优先，原本就通）。

## 四、需人工确认的风险（未列为缺陷）

1. **整请求预算到期丢弃已计费的上游结果**（`main.go:1673-1676, 2131-2142` + `upstream.go:1002-1009`）：总预算约 6 分钟，而单跳 `ResponseHeaderTimeout=60s`（`upstream.go:973`）先于非流式 120s 超时触发——此时上游很可能**已生成完毕**。SDK 幂等键已确认关闭，故客户端重试会产生第二笔上游费用。建议先在生产日志核对 `stream_truncated`/`upstream_timeout` 频次与上游账单的实际偏差量级再决策。
2. ~~**`SSEWriter.roleSent` 锁外访问**~~ —— **已升级为「确认无问题」**（2026-10-11 `-race` 全绿）。
   静态分析判断（`outwire/openai_chat.go:144-150` vs `:91-98`）：`ensureRole()` 不持 `mu` 却读写 `roleSent`，`SetResponseID` 持 `mu` 读同一字段，**若两者被不同 goroutine 并发调用即成真实数据竞争**。
   **`-race` 实测未触发任何 `DATA RACE`**，与静态判断一致——当前调用链确为单 goroutine（心跳 goroutine 只调 `Keepalive`）。
   **但结论仅覆盖「现有测试触及的路径」**：流式事件循环与 `SetResponseID` 并发触发的场景需在 CI 的 `-race` 门禁下长期守住。
   **建议（非缺陷）**：把「实现必须自行串行化」这条契约从 `sink.go:14-15` 的注释提升为**接口方法上的显式约束**——将来若有人从心跳 goroutine 调 `Event`，静默引入的数据竞争不会被任何单测发现。
3. **inwire 三处 `MaxBytesError` → 413 的映射位于 in-scope 之外的 handler**：需确认三条入口路径均已正确 `errors.As` 判型，否则超限会退化成 400。
4. **`tool_choice: none` 在 anthropic 侧被丢弃**（`inwire/anthropic.go:327-329`）：注释论证充分（Anthropic 无法表达），但客户端设 `none` 后上游仍可调用工具，属请求约束静默失效。属产品语义决策。
5. **effort → token 预算的不可逆折叠**：OpenAI `xhigh` → `high` → `anthropicBudget(high)=32768`。方向正确但粒度不可逆，需确认产品接受。
6. **`/admin` 静态资源缓存头相互覆盖**（`server.go:452` `no-store` vs `main.go:554` `immutable`）：内层覆盖外层，最终 `/admin/assets/*` 发 `immutable`。顺序正确无竞态，但管理面「一律不缓存」的设计意图与实际不符。
7. **`upstreamHTTPClient` 未设 `MaxConnsPerHost`**（`upstream.go:966-974`）：理论上可被用于连接耗尽，需确认是否有 OS fd limit / 反代兜底。
8. **`reconcileUsageTotals` 复用同一段 SQL 10 次但只传一份 args**（`usage_archive.go:290-304`）：当前成立仅因零值 filter 无占位符，注释已自认是地雷。建议加 `len(args) == 0` 断言。
9. **`YuanToMicros` 对极小费用单向向上取整**（`balance_dao.go:84-110`）：偏差随调用次数线性累积，当前定价下不现实，注释已给方向。

## 五、核查通过的关键项

**安全**
- **密码哈希**：PBKDF2-SHA256 210k 迭代、16 字节 `crypto/rand` 盐、自描述编码、`subtle.ConstantTimeCompare`（`userauth/password.go:87-141`），强度达标；最小长度 8 位。
- **JWT 会话**：HS256 显式白名单 `WithValidMethods` + keyfunc 二次校验 alg，防 `none`/RS256-HMAC 混淆；`jti` 用 `crypto/rand`；TTL 8h；吊销走 `auth_version` 栅栏，改密/改角色/禁用/登出均递增。
- **API key**：SHA-256 索引查找，**不接受 `?key=` 查询参数**（避免 referer/日志泄漏），禁用/过期/归属/管理员拦截全部 fail-closed。
- **SQL 注入**：`internal/admin` 与 `internal/store` 全参数化，SQL 中拼接的只有字面量列名；`groupByClause` 经 switch 白名单。**无注入面**。
- **路径穿越 / 任意文件写**：admin 导入导出全程走数据库对象，无 `os.`/`filepath` 写操作；SPA 由 embed FS + 白名单服务。
- **密钥泄漏**：凭据列表只回掩码；500 响应不回显底层错误；全 `internal` grep 未发现把 password/api_key/token 传给 `slog.*`；审计只记字段名不记值。
- **CSP**：`default-src 'self'; script-src 'self'`（**无 unsafe-inline/unsafe-eval**）、`object-src 'none'`、`frame-ancestors 'none'`、`form-action 'self'`。无内联脚本，theme-init 已外置并由 `csp_test.go` 守住。
- **CORS**：管理面一律不发 CORS 头（防已登录管理员浏览器被跨源利用），仅 `/v1` 数据面放行 `*`。
- **CSRF**：`decodeJSON` 强制 `Content-Type: application/json` + cookie `SameSite=Strict` + 无 CORS 头；免鉴权 bootstrap 端点与中间件共用同一套 `SameOrigin` 判据（无两套判据漂移）。
- **容器**：多阶段构建、`CGO_ENABLED=0` 静态二进制、非 root 运行且**降权失败时明确告警**而非静默以 root 跑；`.dockerignore` 排除 `master.key`/`admin_auth.json`/`data/`。

**计费正确性**
- 扣费原子性：占位 INSERT + 余数累加（`UPDATE...RETURNING`）+ 带 `balance_cents >= ?` 守卫的扣减三者同事务，失败分支 `defer Rollback()` 使占位行一并回滚，重试不会静默失效。
- 幂等：`(request_id, user_id)` 复合主键 + `fixBalanceChargesPK` 迁移，解决了「同 request_id 跨用户静默漏扣」。
- 余额全整数分/微元，**无浮点参与余额运算**（浮点仅存在于 `cost_total`）。
- 配额：`ReserveQuota` 单事务含检查+预占，`ReleaseQuota` 用 `MAX(0,…)` 防负。
- failover 多次 attempt **只有成功那次计费**（`main.go:2793`）。
- 归档圈批/聚合/删除同事务同谓词，无重复归档；水位仅在明细确已清空时推进。

**工程实践**
- CI 全 action SHA 固定、依赖锁定（`go.sum` + `npm ci`）、前端产物入库一致性校验（whitespace-only diff 豁免）。
- 优雅关闭顺序正确：剪枝（5s 上限）→ `Shutdown(10s)` → 失败则 `Close()` → usage drain（5s）。
- `statusResponseWriter` 正确提升 `http.Flusher`（否则 SSE 首字延迟暴涨）、`writeInternalError` 判断 `Committed()`、`usage` 队列关闭与 `closed` 标志同持一把锁（防 send-on-closed panic）。
- 无裸全局 map 并发写；runtimeReloader 脏标志用 `atomic`、重建用 mutex 且先完整构建再替换；snapshot 遵守「新建→填充→Swap」不可变契约。
- SSE 心跳 goroutine 有 `quit`+`WaitGroup` join；`halfOpen` 名额有配对释放；冷却快照在锁内取值。
