## 一、结论先行

**安全面很干净**：无 `v-html`（XSS 面关闭）、无 `v-for` 缺 key、普通用户路径全部落在后端白名单内、密钥明文不写 storage/日志、admin-only 端点只出现在管理员页。

**缺陷集中在同一类问题：界面上的数字与实际状态脱节。** 三条 P1/H 级缺陷都是这个模式 —— 用户会基于一个已经不准的数字做决策，而界面看起来完全正常。

## 二、按优先级排序的缺陷

### P1 · 设置页：加载失败后保存守卫可被绕过，配置会被默认值整体覆盖

**位置**：`web/src/views/Settings.vue:215`（401 早退）+ `:230`（保存守卫）

守卫只检查 `err`：

```js
// :230
if (err.value) { toast('尚未成功加载...'); return }
```

而 `load()` 的 401 分支直接 `return`，**不设置 `err`**：

```js
// :215
if ((e as { status?: number }).status === 401) return
```

于是：401 → `err` 为空、`loading` 置 false、模板的 `v-else-if="err"` 分支不触发 → **表单以 `form` 的兜底常量渲染（`:168-179` 那组 `131072 / 65536 / 120000 / …`），保存守卫放行**。

**影响**：管理员在跳转登录页前的窗口内点「保存设置」，会用这组硬编码默认值 `PUT /settings` **整体覆盖真实配置**。

**为什么这条最值得修**：`UsersGroups.vue:119`、`Routes.vue:46` 有同样的 401 早退模式，但那是只读列表页；**Settings 是唯一带可写全量 PUT 表单的页面**，同样的写法在这里后果最重。且前端**没有全局 401 拦截器**（我核实过 `api.ts:38-53`）——跳转逻辑在 router guard，不在这条链路上。

**修复建议**：把「表单是否已成功加载」与「错误信息」拆成两个状态。例如 `loadedOnce` ref，守卫改为 `if (!loadedOnce.value) return`；401 分支也要置 `loadedOnce = false`。

---

### H1 · 钱包页的余额是「登录那一刻」的快照，全程不刷新

**位置**：`web/src/views/Wallet.vue:258,268-271` + `api.ts:134,154,171`

余额/待结算/额度全部取自 `session.me`，而 `session.me` 只在 `loadSession()` / `login()` / `bootstrapSetup()` 里赋值。全仓 grep 无其他 `/me` 调用；Wallet 的 `load()`（`:183-205`）只拉 `stats`/`byDay`/`topups`，**从不刷新 `/me`**。

**讽刺的是数据已经到手了**：`stats` 响应本身带 `balance_cents` / `balance_unlimited` / `balance_remainder`（`types.ts:532-534`），总览页用的正是它（`Overview.vue:311-315`）——钱包页却绕开它去读登录快照。

**影响**：用户登录后放着不关，超过实际消费/充值时间再打开钱包，会按一个已经归零的余额继续调用，拿到 402 后完全不知道为什么。同样的陈旧也影响 `Keys.vue:33-36` 的 `quotaHint`。

**修复建议**：`Wallet` 的余额改由 `stats` 驱动（数据已在手，改动很小），或 `load()` 后补一次 `/me`。

---

### H2 · 总览页刷新失败时静默保留旧数字

**位置**：`web/src/views/Overview.vue:275-279`

分支是 `v-if="loading && !stats"` → `v-else-if="err"` → `v-if="stats"`。用户已经拿到过一次数据后点刷新失败时，`stats` 仍非空，第二个分支被跳过 → **旧数字以完全正常的样子留在屏幕上**，无任何「数据已过期」标记。

**对照**：Keys 用 `v-else-if="err"` 整块替换（`Keys.vue:544`）、History 用常驻横幅（`History.vue:345`）。只有 Overview 是这样。

---

### H3 · 充值记录标题的条数写的是总数，不是显示数；截断提示对普通用户不可见

**位置**：`web/src/views/Wallet.vue:863` 与 `:912`

```vue
{{ admin ? '全部用户 · 最近 ' + topupTotal + ' 条' : '最近 ' + topupTotal + ' 条' }}   <!-- :863 -->
<div v-if="admin && topupTotal > topups.length" class="list-foot">                   <!-- :912 -->
```

`topupTotal` 是后端 `total`（过滤后总条数），而实际渲染的是 `topups.length`（上限 50）。

普通用户有 120 条流水时：标题显示「最近 120 条」，表里只有 50 行，且 `:912` 的截断提示被 `admin &&` 挡掉 —— **连提示都没有**。

这与项目自己在 `api.ts:735-746`、`Wallet.vue:737-745` 反复强调的「截断必须可见」原则直接冲突。

---

### M3 · `fmtMoney` 把负数吞成 `0.00`

**位置**：`web/src/fmt.ts:116`

```ts
if (!Number.isFinite(n) || n <= 0) return '0.00'
```

余额被管理员扣成负数时显示「¥0.00」而非「-¥5.00」—— 两者处置动作完全不同。充值流水「调整后余额」列同样受影响。管理端扣减接口允许负 delta（`Wallet.vue:403-417`），**这条路径可达**。

## 五、做得好的地方（避免误改）

这几条质量高于平均，审计中逐一核实过：

1. **无 `v-html` / `innerHTML`** —— 全 `web/src` 零命中，XSS 面关闭。
2. **所有 `v-for` 均有 `:key`** —— 5 个大页面共 23 处全部带 key。
3. **加载错误与空状态严格区分** —— 各页都有独立 `err` 持久态 + `v-else-if="err")` 分支，避免了「请求失败呈现成暂无数据」这个经典误判。
4. **防连点机制完整** —— 按行 Set / 按行 Map / 全局 flag 三种粒度按场景选用。
5. **无乐观更新** —— 全部是「await 成功 → 重取」，不存在回滚失败问题。
6. **后端 4xx message 原样展示** —— `e instanceof ApiFail ? e.message : ...` 贯穿所有表单。
7. **凭据明文永不下发** —— 后端只回掩码（`types.ts:80`），输入框用 `type="password"`，编辑时不预填。
8. **密钥复制用完即抹** —— `fmt.ts:264-276` 有 `execCommand` 回退且复制后立即清空临时节点。
9. **N+1 已消除** —— 多处用 `Promise.all` 或 `allModels()` 一次取全。
10. **AppModal 焦点管理扎实** —— 嵌套弹窗栈顶机制 + `inert` 引用计数页面锁 + Esc 与 `dismissable` 配合。
11. **余额/配额/402 的文案是可行动的** —— 明确写出「会被 402，请联系管理员充值」，而不是只显示一个数字。
