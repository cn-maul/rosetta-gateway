## 二、2026-10-11 全量审计（`audit-2026-10-11.md`）

静态源码审计，四路并行分模块 + 交叉复核。**基线**：`go build` / `go vet` / `go test ./...` 全绿（17 包）。

**结论：无 P0。** 无鉴权绕过、无 SQL 注入、无密钥泄漏、无重复扣费路径。计费主干（事务原子性 + 幂等键 + 余额守卫）经逐行核对正确。

按处理优先级排序的三条（都是「故障时静默丢账」，不需攻击者即可触发）：

1. **批量落库整批失败 → 最多 50 条用量与扣费静默丢失**（`main.go:2728-2748`）：用户消耗上游 token 却完全免单，且配额被永久放宽
2. **查价失败即永久记 0**（`usage_dao.go:327-348`）：同样免单，且 `RecomputeCost` 在生产代码中**无任何调用点**，无自动修复路径
3. **Anthropic `content` 单对象被静默转为空消息**（`inwire/anthropic.go:473-482`）：本轮用户输入消失且不报错，OpenAI 侧已有兜底可对齐

**唯一可能造成权限放宽的条目**：P2-6 组白名单悬空回落 `AllowAll()`（`snapshot/rebuild.go`），需实测确认 `access_keys.group_id` 的 `ON DELETE SET NULL` 行为。

**重要**：报告内 9 项「需人工确认风险」未经运行时验证，**不应直接按已确认缺陷排期**。其中并发相关结论建议跑 `go test -race` 升级为确认结论。
